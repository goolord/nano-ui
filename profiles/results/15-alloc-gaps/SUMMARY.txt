nano-ui ImGui-technique gap pass: text lookups + stateless widget churn
date: 2026-09-12 (Linux x86_64, GHC 9.14.1, -O2 -mavx2, RTS -N1 -A64m -T -I0)

scope: the applicable/not-already-implemented items from the ImGui
optimization list. Capacity pre-allocation with geometric growth and
per-frame pointer resets were already implemented (DrawArena, NodeArena,
SpanArena, command store); baked corner trig tables already exist
(cornerCosSin, Draw.hs), and retained corner meshes were previously
measured as a regression (13-phase2-7-8-findings). This pass targets the
two remaining fine-grained allocation sites.

baseline: HEAD f6c5007, profiles/results/15-alloc-gaps/baseline-profile.txt
final:    commits 259f72f (text lookups) + 0f34e1f (idle widget churn)

raw captures in this directory:

commits:
  259f72f perf(sdl): share glyph quads and pack text lookup keys
  0f34e1f perf(paint): skip style/response churn for idle widgets

phase A - text lookup allocation (259f72f):
  - ASCII glyph cache stores the shared Maybe GlyphQuad instead of
    rebuilding Just q per character.
  - non-ASCII quads memoised per FontMetrics (epoch-invalidated).
  - kerning key packed into one Int on the per-font cache (no pair tuple).
  - run cache keyed by Text alone (font id is implicit).
  measured: allocation-neutral to slightly positive. The whole-run cache
  already covers the common text path; 100x Button 552.1 -> 548.2 KB,
  DemoUi runFrame 514.3 -> 513.5 KB, Label/Table unchanged. No timing
  change. Kept because the residual per-glyph fallback now allocates
  nothing (locked by the new gate below).

phase B - idle widget churn (0f34e1f):
  - buttonLayoutEx returns the response unchanged unless hover/click
    actually changes, and folds the two record updates into one.
  - widgetVisualStyle only walks floating ancestors for the node types
    that consult them, and reuses the base Style when the resolved
    background is unchanged (idle widgets skip the final record update).
  measured (KB alloc/frame, SDL profile):

    Tab: Table (14 x 5)      421.8      421.0

  100x Slider and 100x Box are unchanged because their base style is
  already a fresh record (clearStyle path); no regression.

phase D - regression gate:
  nano-ui-sdl-bench now runs glyphLookupGate before the benchmarks. It
  warms all probe characters, then measures allocated_bytes over 20000
  varied-char fmGlyph lookups and fails if the average exceeds 1 byte
  (measured 0.000 B/lookup). This catches reintroducing a per-character
  Just/GlyphQuad on the fallback path. Note: the probe walks a shared
  Char list because T.index itself allocates in this benchmark context.
