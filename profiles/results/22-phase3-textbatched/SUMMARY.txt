Phase 3 (part 3): batch per-character text glyphs into one reservation
date: 2026-09-12 (Linux x86_64, GHC 9.14.1, -O2 -mavx2, RTS -N1 -A64m -T -I0)

Problem: when the shaped-run cache misses (fmRun -> Nothing), pushText
emitted one pushQuad per character, each with its own withVerts closure,
capacity check and Rect. Text-heavy fallback paths (non-ASCII, RTL, RGFW
external text) paid a closure per glyph.

Change: new withVertsReserve reserves an upper bound (T.length txt quads)
and commits the exact count the walk reports; pushText's per-character walk
pokes each glyph/fallback rect at running offsets in that single
reservation. Vertex/index order and counts unchanged.

Measured ui/runFrame alloc: medium 326 -> 323 KB, large 677 -> 670 KB
(-29.1% vs 945 KB baseline). Fallback-heavy text benefits more; the SDL
run cache path was already one quad per run.
