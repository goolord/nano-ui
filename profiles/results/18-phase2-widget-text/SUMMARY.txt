Phase 2 (part 1): cache widget-label placement across frames
date: 2026-09-12 (Linux x86_64, GHC 9.14.1, -O2 -mavx2, RTS -N1 -A64m -T -I0)

Problem: paintWidgetForeground called widgetTextPlacements every frame for
every button/checkbox/radio/select/tree row, building a fresh
[(Text,Float,Float,Float,Float)] list even when text, style, font and rect
were unchanged. Profiling attributed ~12% of frame allocation to this site.

Changes:
- New WidgetTextCacheEntry + Context.ctxWidgetTextCache (IntMap keyed by node
  slot). Key: node type, style idx, font size, display text, rect.
- widgetTextPlacements now serves cacheable labels (button/select/tree/
  checkbox/radio) from the cache; data-dependent nodes (text input/area,
  colour picker, slider) still compute.
- Cache cleared by clearMeasureCache and setTheme, alongside the span cache,
  so font/DPI/theme changes cannot serve stale geometry.

Measured:

               large  945 -> 844 KB (-10.7%)
