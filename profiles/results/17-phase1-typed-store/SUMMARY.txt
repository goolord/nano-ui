Phase 1: remove whole-store diffing from individual writes
HEAD before: 96571ee
date: 2026-09-12 (Linux x86_64, GHC 9.14.1, -O2 -mavx2, RTS -N1 -A64m -T -I0)

Changes:
- NanoUI.Store: new ptrEq/eqByPtr. WidgetStore Eq now short-circuits each
  map field with a physical-equality check, so record-updated stores that
  rebuild one map no longer compare every map structurally.
- NanoUI.Context.diffKeys skips physically-equal maps.
- New targeted single-slot helpers in NanoUI.Context:
  writeStoreInt/writeStoreFloat/writeStoreText (+Flag mirror variants) and
  writeStoreBool. They compare only the target slot, update one map, damage
  the owning widget and markDirty; an equal write is a no-op. setStore
  remains the fallback for genuine whole-store replacement.
- Migrated hot single-field writes: setStoreBool, checkbox toggle, slider
  value.

Measured (ui/runFrame, taste-bench): small 17 KB / medium 455 KB /
large 945 KB -- unchanged. Store diffing was not a top allocation site on
this workload; the win is CPU on per-frame `oldStore /= newStore` and
`storesEqualExceptFloat` comparisons in Damage, which now short-circuit.

Full demo alloc/frame unchanged (516.9 / 509.7 KB), confirming the macro
and checkbox/slider writes were already guarded.

Verification: cabal test all PASS; nano-ui-id-bench zero-alloc gate PASS;
sdl glyph-lookup gate PASS.

Note: the plan's `slotKey`/owner-targeting distinction is preserved:
targeted helpers damage the owning WidgetId; auxiliary-slot writes still
route through conservative setStore where the owner is ambiguous.
