# Revision history for nano-ui

## Unreleased

* Build configuration favours compile time. `nano-ui` no longer forces `-O2` and no longer depends on `ghc` or `effectful` (only `effectful-core` is used). The workspace builds at Cabal's default `-O1` and drops `-fspecialise-aggressively`, `-flate-specialise`, `-fmax-worker-args=32`, and `-funbox-strict-fields`: on the headless frame profiler those flags made the core slower at runtime as well as slower to build. `INLINE` stays only on small bodies and inner-loop helpers. A clean `-j1` build of the core library drops from 4 min 25 s to 57 s, and the headless frame profiler runs about 3% faster than the previous `-O2` build. `docs/development.md` records the measurements and how to opt into `-O2` locally.
* Layout: `NanoUI.Layout.Solve` no longer imports the widget, context, or draw layers, so widget and context edits stop recompiling the solver. Per-solve inputs travel in one `SolveEnv`; arena columns are named constants with small readers/writers; wrap and fit memos share one `WidthMemo`/`memoizeWidth` implementation (memo tags are now zero-initialised); flex grow/shrink reads each child's sizing once per pass. `solveLayoutWithResolver` is renamed `solveLayout`; the unused `solveLayoutWith`, `positionNode`, and six-argument `solveLayout` are removed, as are the arena's individual memo and scratch fields and accessors.
* Fix: padded 2D scroll containers applied their padding twice when positioning children.
* Fix: in `-O2` builds, the anti-aliased fringe of rounded borders could be drawn from garbage vertices. GHC 9.14.1 miscompiles the `FloatX4#` broadcast/pack/unpack arc-offset code once it is inlined into a loop (liberate-case derived the y lane from the x centre); `concentricOffsetsSIMD` now uses scalar arithmetic with bit-identical results, and its `strokeStripNormalsSIMD` alias is removed.
* Fix: in builds without optimization, every frame was treated as a font configuration change, forcing full-window damage and clearing the text and layout caches. The metric-source identity check compared an unevaluated selector thunk; it now compares evaluated values.
* Context: `NanoUI.Context` keeps its API but is split into `Context.Core`, `.Scroll`, `.Animation`, `.Overlay`, and `.Drawing`; state records gain `gets*`/`modify*` accessors. Removed the unused `writeStoreIntFlag`/`writeStoreFloatFlag`/`writeStoreTextFlag`, the `menuPointerGestureActive` alias (use `getMenuPointerGesture`), and `Store.allSlotTags`/`eqDynMap`. Store slot tags derive from a `Slot` enumeration, so a new slot can no longer be missed when a widget's state is deleted. `CoreDebugSnapshot` holds the RTS sample as `dbgRts :: RtsStatsSnapshot` instead of copying its fields; `bytesMb`, `nsMs`, `rtsFields`, and `formatRtsRows` are removed.
* Fix: a frame that scrolled and also changed dynamic store values could skip full damage. Rewriting an unchanged boolean slot or scroll offset no longer wakes the loop an extra time.
* Fix: `resolveDamageRect (DamageUnion a b)` treats an empty side as the identity; `DamageUnion x DamageNone` previously stretched the damage to the window origin. The law-breaking `Semigroup`/`Monoid` instances for `DamageBounds` are removed; use `DamageUnion`.
* Removed aliases: `tomorrowNightMinTheme`, `tomorrowLightTheme`, `tomorrowMidnightMinTheme` (use the `…DarkTheme`/`tomorrowMinLightTheme` names), `base16Theme`/`base16ToTheme` (use `themeFromBase16`), `Base16ColorScheme` (use `Base16`), `base0a`…`base0f` (use the `base0A`…`base0F` fields), `textColor` (use `fontColor`), `fontStrikethrough` (use `fontStrike`), and `cols` (use `gridCols`).
* Removed unused API: the vector types and arithmetic in `NanoUI.SIMD` (the quad and vertex writers remain), `Animatable`'s `lerp` and `distance` methods, and the exports of `NanoUI.Runner`'s internal timing and click-tracking helpers and `NanoUI.Id.hashSrcLoc`.
* Fix: `fromComponents` for `Color` defaults a missing alpha to 1 instead of 0.
* Testing: `assert`, `assertEq`, `assertGt`, and `assertLt` take `HasCallStack` and print the failing call site and compared values (the comparison assertions now need `Show`). Removed `failWhen`, `assertNeq`, `runFrameDraw`, `eval2Ui` (use `warmup2`), `runClickMsgs`, `closeSpanBottom`, `closeSpanCenter`, the Harness `modifyIORef`, `spanLabelYs` (use `spanYOf`), `spansHas` (use `hasText`), and `checkLabelAlignEnd`; `measureResp`, `clickAt`, and `spanYs` are no longer exported; Harness now exports `keyInp` and `tabInp`.
* nano-ui-diagrams: removed the unused `NanoUITextBackend`, `Range`, `ScaleType`, `hitTestChart`, and `diagramPointAt`. `domainToPlot`/`plotToDomain` take only the domain and `chartMargins` drops its unused style argument. The package depends on `effectful-core` instead of `effectful`.
* nano-ui-form: removed `nanoForm` (use `nanoFormLive`), `FormIdle`, `fssDirty`, and `clearActiveFormPrefix`. `NanoUI.Form.Types` no longer re-exports backend names; import them from `NanoUI.Form.Backend` or `NanoUI.Form`. `Validation` adds `validate`, and `inputRadio` decodes text input like `inputSelect`. The package depends on `effectful-core` instead of `effectful`.
* Widget fixes: `select` and `colorPicker` report `respChanged` only on the frame the value changes (previously every later frame, so `selectEmit` emitted continuously); text areas handle Alt+Delete/Left/Right as word edits like text inputs; custom widgets and `canvasWith` see clicks resolved from the pointer queue; `TabResponse` forwards `respSubmitted`; `boundedSelect` offsets by `minBound`.
* Fix: `textInputPassword`, and so `nano-ui-form`'s `inputPassword`, displayed the typed text in the clear. Password fields now show one `*` per character (caret and selection stay aligned) and refuse Copy and Cut from both the keyboard and the context menu. Text-input nodes carry the new `textInputFlagPassword` style bit, and `processTextInput` takes whether copying is allowed.
* Fix: a text area rebuilt its line buffer from the whole document after every edit, because the save path deleted the buffer it had just stored. A focused colour-picker field no longer rewrites the widget store on every frame when its text is unchanged.
* Fix: removing a radio group, select, or colour picker left some of its state in the widget store, because those slots used ad-hoc tags that `deleteWidgetState` does not enumerate. They are now `Slot` constructors (`slotRadioInit`, `slotSelectSeen`, `slotColorBase`).
* Widget API: `Responding`, `Clickable`, and `RightClickable` merge into `HasResponse`. Animation takes a `Transition` (`Tween` or `Spring`) first — `animate t from to`, `animateTo t target`, `animateToA t value` — replacing the `animateEase*`, `animateToEase*`, and `animateToSpring*` variants. Tabs use `tabsWith`/`tabBarWith` with `TabsConfig` instead of `tabsEx`/`tabBarEx`/`tabsEmitEx`. Menu items gain a `MenuItem` record with `menuItemWith`, replacing the primed and icon variants; text menu actions are a `MenuAction` type instead of `menuActionCut`… integer codes. Removed aliases: `withContextMenu` (use `contextMenu`), `useTab`/`useRadio`/`useEnumSelect`/`useEnumRadio` (use `useEnum`), `useTabIdx` (use `useInt`), `tabRespClicked`/`tabRespChanged`/`tableRespClicked`/`tableRespChanged`, `mkTab`, and `useClickGesture`. `TextArea`'s `KeyInput` becomes `TextAreaEvent`; `SplitPane`'s `DropTarget` becomes `PaneDrop`; `TextBuffer.Cursor` derives `Ord` in place of `compareCursor`/`cursorBefore`; `widgetInteract` receives the resolved `Response`.
* Frame and draw internals are split along their seams: `NanoUI.Draw` re-exports `Draw.Types`, `Draw.Arena`, `Draw.Shapes`, and `Draw.Text` (the context types import only `Draw.Types`, so shape and text edits no longer recompile the context layer); `NanoUI.Frame.TextEdit` re-exports `TextEdit.Menu`, `Frame.TextInput`, `Frame.TextArea`, and the pure `TextArea.Geometry`; window overlay painting lives in `Frame.Overlay`. Draw-command flushing moved out of the inlined `push*` fast path, text areas share one scroll-bar lane calculation, and select dropdowns, the context menu, and window overlays share one menu-panel painter. `FrameResult`/`FrameReduceResult`, `Draw.Vertex`, `pushBackdropDim`, `getCurrentClip`, `foldDrawCmds`, `snapToPixel` (use `onGrid`), `measureTextWrapped`, `wrapTextLines`, `truncateTextAdvance`, `truncateTextWith`, and other unused frame helpers are removed; `scrollBarGeomFor` and `wrapTextLinesIO` no longer take `FontMetrics`.
* Fix: hovering a text area's scroll bar rebuilt and re-measured the whole document every frame; it now uses the cached content extent. The text-area viewport sync no longer writes a stale store back over a freshly filled content cache after each edit. The select dropdown accent bar uses the shared menu constants.
* `NanoUI.Widgets` is split into focused modules (button, checkbox, slider, select, combo, display) behind the same export facade, so editing one widget no longer recompiles the rest; `Widgets.Drop` no longer takes 13–16 s to compile at `-O2`.
* RGFW fixes: repeated typed characters (e.g. "ll") are no longer collapsed; the cursor shape updates on drawn frames, not only skipped ones; copy and paste use the system clipboard instead of a process-local buffer; an invalid key character no longer stalls the rest of an event batch. Mouse press/release flags are set the same way as in SDL.
* RGFW API: `runRgfwSession`, `runRgfwSessionReduce`, and `runRgfwSessionReduceCustom` are renamed `runRgfwApp`, `runRgfwAppReduce`, and `runRgfwAppReduceCustom`, matching SDL. `NanoUI.Backend.Rgfw` no longer exports the debug sampler internals; use the core `formatFpsRows`/`formatDrawRows`/`formatCoreRtsRows`. `RgfwDebugSnapshot` is `{dbgCore, dbgFrame}`. The unused software-surface functions and the bindings' surface, init, and window-creation imports are removed; the bindings gain key/modifier constants and clipboard access. The embedded Cozette renderer shares one scaling path, one clipped blit, and one text walk with the OpenGL atlas.
* SDL fixes: the version probe no longer reads uninitialised memory through a wrong FFI signature; the clipboard reads SDL3's `bool` results correctly; the per-string measure cache is bounded. `NANO_FORCE_SCALE` and `NANO_FRAME_TRACE` are read once, and the render scale is only reset when the display scale changes. The font, run, kerning, and dynamic-font caches share one bounded cache.
* SDL build: the `simd` flag defaults to off and only applies on x86-64, so default builds run on CPUs without AVX2; C sources build at `-O2` without forced `-O3`/fast-math. `NanoUI.Sdl.Input.pollEvents` returns a list. Core `NanoUI.Input` gains `applyMouseButton`.
* nano-ui-demo: shared demo modules compile once in an internal `demo-common` library instead of once per executable, the executables no longer force `-O2` or `-mavx2`, and the one-frame `nano-ui-demo` example executable is removed.
* RGFW renders with OpenGL. The session opens an OpenGL 3.2 core context (`RGFW.createWindowGL`, `swapBuffersGL`) and `NanoUI.Rgfw.Gl` uploads the core's draw buffers as-is, one scissored draw per command, instead of rasterizing into a CPU surface and blitting it. Text is drawn as quads from a glyph atlas that the Cozette software blitter bakes at the current scale, so glyph pixels match the software path; 4-corner gradient quads are now interpolated rather than averaged. GL entry points resolve through RGFW's loader, so no link dependencies are added. The software rasterizer (`NanoUI.Rgfw.Render`, `NanoUI.Rgfw.Surface`) remains for tests and the profiler.
* Font backend effects are explicit: `FontMetrics` gains optional `fmBackend`; `prepareFontMetrics`, `prepareFontMetricsMany`, `lineWidthIO`, and `measureTextIO` prepare immutable layout snapshots, while `drawGlyph`/`drawRun` perform native rasterisation in IO. `RunQuad` is strict. Pure custom-font record constructors should set `fmBackend = Nothing`. SDL no longer hides font queries or atlas mutation in pure callbacks, and its memory-font stream owns its bytes. Backend callbacks reject closed native handles. See `docs/data-state-audit.md` for migration and verification details.
* Numeric plots retain unboxed `PointsXY` vectors; numeric `*Vec` helpers accept generic boxed/unboxed/storable input. Ear clipping relinks mutable neighbor indices instead of copying its coordinate vector after every ear. Sampling, hover selection, stroke geometry, table metrics, and font metrics avoid boxed numeric intermediates and repeated list work.
* Chart caches are context-owned and invalidate on metric generation, theme, style, and chart changes. Font caches use bounded strict updates and FIFO queues, numeric widget/form/tick text uses builders, text-area/focus/combo lookup is total, and extreme finite tick values no longer overflow during formatting.

* Remove retained inner range lists from RGFW triangle rasterization and color-picker checkerboard painting. Optimized-Core inspection confirms numeric loops in both paths; RGFW regression tests cover triangle pixels, winding, clipping, and degeneracy. See `docs/range-loop-audit.md` for the remaining `forM_ [` audit.
* Form adapters follow the collection-friendly widget APIs: named select/radio inputs, unnamed select inputs, and `defaultErrorView` accept `Foldable` collections.
* Table column sizing/classification, headers, resolved widths, and cell layouts use vectors throughout indexed layout, including reordered and hidden columns. Select/labelled-select/layout-select APIs, `selectEmit`, `comboBox`, `radioFieldset`, and the `tabs` / `tabBar` / `tabsEmit` families accept `Foldable` option collections; tab bodies retain their selected-only execution semantics.
* Polygon tessellation's ear-containment test checks other vertices against the candidate triangle with the correct argument order; regression coverage includes concave polygons in both winding directions and explicitly closed paths.
* Indexed hot-path collections: polygon ear clipping uses unboxed vertex vectors and scans candidates without allocating a list of other vertices; text-area painting shares a line vector between selection, content and caret rendering, eliminating repeated list-prefix scans during multiline selection. Tree rows/responses and `simpleTable` cell rows use vectors for indexed navigation and encoding.
* Collection-friendly APIs: `table`, `tableEx`, `tableCfg`, `sortRows`, `tree`, `kvBlock`, `hstack`, `vstack`, `registerImages`, `decodeMessages`, `reduceMessages`, `reduceUpdates`, and plot constructors `line` / `scatter` / `bar` / `area` / `step` accept `Foldable` inputs. `simpleTable` accepts any `Foldable` outer row collection. Existing list calls remain valid; order follows the input's fold order. Message reduction and bulk registration fold directly without intermediate result lists; image registration still attempts every image after a failure. Plot `*Vec` constructors remain the direct, conversion-free vector entry points.

* Keyboard access for the input controls. Every `buttonStyled`-based widget is now a Tab stop and activates with Enter or Space while focused, so plain buttons, tab headers, table sort headers, menu items, menu-bar titles, window close buttons, tab-strip paging chevrons and the table's "Show all columns" button all work from the keyboard. `checkbox` toggles on Space/Enter, `slider` steps with the arrow keys (1% of its range per press), `radioFieldset` moves the selection with the arrow keys, the `knob` / `toggleSwitch` custom widgets adjust with the arrows and flip on Space/Enter. The shared `keyActivated` helper (`NanoUI.Widgets.Behavior`) folds Enter/Space into a click for leaf widgets. New integration tests cover each control (`keyboard-button`, `keyboard-checkbox`, `keyboard-slider`, `keyboard-radio`, `keyboard-toggle`, `keyboard-tab-header`, ).

* Text areas honour their node's `layoutFontSize` (`fontSize` / `fontSizeScale` on the editor layout): paint, hit-testing, caret/selection geometry, cursor mapping and — crucially — the scroll range all resolve the node font through the new `resolveTextAreaFont` (`textAreaContentGeom` shares it with the scroll/cursor paths), so a zoomed editor scrolls all the way to the true content extent instead of clamping at the unzoomed line height. The text-area content extent is cached (`textAreaContentMetrics`, `slotTextAreaContent*`) and only re-measured when the text is edited or the node font changes, so a large document is no longer re-measured character-by-character every frame. Menu chrome polish: context menus are now flat by default — `menuItem` / `menuItemWithShortcut` / `menuItemWithIcon` render as full-width, left-aligned rows with a rounded hover highlight and an accent marker instead of boxed buttons, matching the text-field context menu (new `buttonFlagMenu` style flag + `menuItemVisualStyle`; `NanoUI.Widgets.Menu.menuButton` gives a flat, label-sized menu-bar title that tints while its drop-down is open, centred with no hover accent marker via the separate `buttonFlagMenuBar` flag), drop-down rows stack with no gap between them, menu buttons skip the hover fade animation (their highlight snaps on and off), and the generic menu now matches the text-field context menu pixel-for-pixel — 28px rows (`textEditMenuItemH`), the same label inset (`textInputMenuItemPadX` + content inset), a square full-row hover fill, the same 2px accent marker geometry, inset 9px separator bands, and the 148px minimum width. All of the menu metrics now live once in `NanoUI.Font` (`menuOuterPad`, `menuItemPadX`, `menuItemRowH`, `menuSepH`, `menuMinW`): the generic menu (`Widgets.Menu`) and the bespoke text-field painter (`Frame.TextEdit`) both delegate to them, the menu items measure with the full label gutter so the popup panel sizes identically (`Solve.measureWidget`), and the generic menu's hover fill and 2px accent marker are painted full-bleed across the popup panel via the enclosing popup rect (`Paint.popupPanelRect`) instead of being inset by the popup padding. A context-menu separator renders as a 1px rule inset exactly `menuItemPadX` from the panel edge, centred in its band — generated from the same `menuSeparator` widget the flat-drop-down rows use. A widget-anchored popup keeps its left edge aligned with the anchor even when the anchor sits inside the window margin (`clampPopupX`), so the first menu-bar item's drop-down lines up with it like the others. Text-field menu actions (Cut/Copy/Paste/Select All via `applyTextAreaMenuAction` / `applyTextInputMenuAction`) now focus the field, so the selection highlight and caret appear when the action is chosen from a menu that isn't over the field. SDL backend: a `DamageFull` frame clears the retain texture to the window colour before drawing, so text that moves or shrinks over a bare window background (no full-window panel node) no longer ghosts against the previous frame. SDL dialogs: the completion callback now records its result before waking the event loop (the woken frame used to poll `FileDialogPending`, skip, and wait for an unrelated event), `EvRefresh` marks `inputWindowRedraw` so `needsRedraw` actually runs that frame, consumed dialog callbacks are freed one poll after retirement (never while SDL might still be unwinding the wrapper), the dialog-completion window-raise warning only fires when raising the window actually failed (a failed restore on an un-minimized window is a platform quirk, not an error), and `textAreaWith` seeds the `slotTextAreaScroll` store key at init so wheel/drag offsets reach the editor without a prior focus click. Cut/Paste from a text-field context menu now pulses `respChanged` through the text-area store even though the frame carries no keys or chars (`slotTextAreaChanged`, set by `applyTextAreaMenuAction` only when the text actually changed, so selection-only actions stay quiet). The text-area buffer cache is invalidated together with the content-extent cache on every text write, so a cached line-split document can never outlive its stored text. The hover accent marker geometry moved into `NanoUI.Font` as `menuAccentW`/`menuAccentInset`, derived by both the generic and text-field menu painters, and `menuSeparator` renders a fixed 1px band. Build flags: `-funbox-strict-fields`/`-fmax-worker-args=32` are scoped to the hot packages (nano-ui, nano-ui-sdl, nano-ui-demo) instead of `package *`, and `nano-ui-sdl` drops `-fspecialise-aggressively` (the flag family that blew up Paint.hs's compile time).
* New standalone example: `nano-ui-sdl-notepad` (run with `cabal run nano-ui-sdl-notepad`). A whole notepad in one `NanoUI` function: a locally implemented menu bar (File / Edit / View / Help) whose drop-downs are anchored popups over the generic `popup` primitive, wired to real actions — New, Open/Save/Save As through the SDL file dialogs (a single strict `BS.readFile`, then a lenient UTF-8 decode), Cut/Copy/Paste/Select All via `applyTextAreaMenuAction`, editor-only zoom (Ctrl+= / Ctrl+- / Ctrl+0 and View-menu items), a status-bar toggle with live word/char counts and zoom, an Exit item that terminates the app via `exitSuccess`, and an About modal. `--selftest` drives the menu bar, the menu Select All path and editor zoom headlessly. Supporting framework change: the text area is now caption-less — `textArea :: Text -> ...` and `textAreaWith :: Layout -> Text -> ...` take only the initial text and fill their whole node rect, so callers pair them with a separate `label` (the demos, form package and tests were updated). `textAreaWith` lets the editor grow to fill its parent (`textArea` is `textAreaWith textAreaLayout`).
* Tab bars scroll instead of overflowing: a horizontal `tabs` / `tabBar` strip that outgrows its width hands its headers to a hidden, bare `scrollHorizontalHidden` scroller and pages them with thin chevron buttons on the left and right. The framework owns the clip, offset store, damage, and wheel; the strip only adds the buttons and maps up/down wheel notches onto the same horizontal offset. Scrolling left and right works through every input — the buttons, the mapped vertical wheel, and left+right (horizontal) wheel, which the framework scroller applies itself — and no scrollbar ever appears. While the labels fit, the strip renders exactly as before — no scroller, no buttons; when it scrolls, the headers look exactly the same (the right arrow is right-aligned by growing the scroller between the two). Vertical orientations are unchanged. Supporting framework changes: `ScrollConfig` gains a `scrollBare` flag (a bare scroller paints no well — no input background, no border — it only lends its clip and offset, and partial-retain backdrops walk past it to the panel behind), and the wheel now addresses hidden-chrome scrollers too (`scrollWheelSuppressed`: only a `ScrollNone` axis ignores the wheel — thumb dragging still skips hidden bars, which have no lane to grab). The test harness gains `drawQuads` for asserting on rasterised chrome (wells, scrollbar lanes) that span queries cannot see.
* Colour picker refactor: the GUI panel is now a composite widget — a large square SV field with a vertical hue slider (and, for the new `colorPickerRGBA`, a vertical alpha slider over a checkerboard) plus editable R/G/B(/A), H/S/V and hex fields whose labels sit inline to their left. The channel fields sit in percent-width columns so the R/G/B(/A) and H/S/V rows stay column-aligned (the RGBA row reserves a fourth column). The SV field keeps a 1:1 aspect (centred in the canvas), the hue/alpha bars match its side, and the compact `Current`/`New` swatches are square-cornered with a checkerboard behind them so translucent colours read correctly. Edits parse live on every keystroke and recolour immediately; fields resync from the live colour whenever they are not focused, so dragging a slider updates the numbers. A held press keeps sampling the SV field (the drag-key bookkeeping used to blank the track and snap the colour to white on the second frame). `colorPicker` stays the opaque RGB variant (`#RRGGBB`), `colorPickerRGBA` adds alpha (`#RRGGBBAA`), and `colorPickerToHexA` / `colorPickerParseHex` back the eight-digit form. The canvas geometry (`colorPickerGeom`) now takes a show-alpha flag and reports `cpgHue` / `cpgAlpha` / `cpgPreviewX`. Supporting framework change: `NodeTextInput` gains a bare mode (`textInputFlagBare` / `textInputBareMode`) — a caption-less, chrome-less box that fills its node rect — so callers can pair it with their own label; it threads through measure, geometry, hit-testing, cursor, spans and paint without touching the captioned/search paths. SDL demo: the accent picker is now the RGBA variant (state keeps the eight-digit hex).
* Word-wise editing keys for single-line text fields (`textField`, `searchField`, `comboBox`): Ctrl or Alt plus Backspace/Delete deletes the previous/next word, plus Left/Right moves by words (Shift still extends the selection), matching the text area (`applyKey` in `NanoUI.Widgets.TextInput` now takes the word flag and routes to `deletePrevWord` / `deleteNextWord` / `moveWordLeft` / `moveWordRight`).

* Combo box: `comboBox placeholder options value` is the search field (same single-line edit engine, placeholder) styled like a dropdown — a select chevron in the right reserve that flips up while the list is open, no magnifier/clear chrome, and the editable text clips left of the chevron. The dropdown is visible exactly while the field holds focus; typing filters the options case-insensitively (empty text lists all of them) and only edits the live field text — the committed value (and the `respChanged` pulse) changes on Enter (which commits the highlighted row, set by hovering or Up/Down), on clicking a row (which also defocuses the field, so the dropdown dismisses with the pick), or when the field loses focus; Escape reverts the live text to the last committed value. Up/Down move the highlight, and the list scrolls: the wheel (vertically over the rows, horizontally when the widest rows overflow the width — the scroller underneath never moves) plus scrollbar thumbs that sit flush against the dropdown's border; the list has no outer margin (rows start flush at the dropdown's top edge), menu rows show the pointer cursor on hover, and the horizontal bar appears only when the widest row overflows, with the combo's drop rect reserving space for it, so it never covers the bottommost row (`comboDropRect` / `comboScrollGeom` share the lane geometry between the painter, the pick guard, and the widget's drag gesture; combo picks are press-only and never fire from the lanes, so finishing a thumb drag cannot commit a row). Escape dismisses the dropdown by clearing focus. The value is free text — options are suggestions — and `respChanged` uses select-style semantics (value differs from the passed-in `initial`, so callers write the result back like they do for `select`). While a combo's dropdown is up, every frame redraws with full damage (the floating list is overlay-painted, so clip frames would leave stale rows in the retained texture). Presses on the open dropdown no longer clear text-input focus first (`finalizeTextInputFocus` skips when an open dropdown overlay owns the pointer), and the select dropdown finalizers (`pick`, `close-on-outside-click`, overlay cache, hover/cursor owner) treat a focused option-carrying `NodeTextInput` as a dropdown owner. SDL demo: the Controls-tab font picker is now a combo box fed by `listFontFamilies`, and the theme picker became a radio fieldset again.

* Table horizontal scroll reaches the end of the columns: a native 2D scroller's per-axis range and thumb now subtract the opposite axis's live gutter, so the last column clears the vertical scrollbar lane instead of stopping partly under it (`scroll-2d` range/thumb geometry moved into `scrollBarLayoutIn` / `scrollBarLayouts2D`). The padded-2D trailing-padding reach is now measured against the lane-shrunk viewport.
* SDL runtime font-family switching: `NanoUI.Backend.Sdl.setSdlUiFont` publishes a requested `NanoUIFont`; the display thread reopens the base font, resets the glyph atlas, rebuilds the font cache and text resolver, and invalidates measurements before the next frame. The `SdlFontCache` primary source is now an `IORef` (`setSdlFontCacheSource`), and `SdlEnv` gains `sdlFontSourceRef` / `sdlFontRequestRef` / `sdlFontAppliedRef` (the old `sdlFontSource` field is replaced by `sdlFontSourceRef`). `NanoUI.Backend.Sdl.listFontFamilies` enumerates installed font family names (usable as `FontSearch` tokens). The SDL demo's Controls tab replaces the "Theme (radio)" fieldset with a font-family selector wired to `setSdlUiFont`.
* Scrollbar track chrome is opaque instead of a near-invisible translucent tint, and is derived from the surface it sits on (the scroll well / floating window body), so the lane reads against dark themes.
* Floating window body has one side-pad of breathing room under the title chrome and above the bottom edge (matching the window's left/right padding); the window's minimum height accounts for the body gap.
* Pane-grid pane drags mark the frame dirty while the button is held, so the drag ghost follows the pointer at the display cadence instead of the debug HUD's 4 fps refresh.
* SDL demo: the progress bar moved out of the Controls tab onto its own Progress tab.
* Table horizontal scrollbar moved to the bottom of the full table: the body scroller is now a real 2D scroller (Auto/Auto) that owns both bars, while the header scroller is chrome-less and just follows the linked horizontal offset. The bar no longer sits directly under the header row, spans the table width at the table's bottom edge, and its live 2D gutter logic reserves the lane exactly while the columns overflow (replacing the previous-frame lane flag, the header lane spacer, and the frozen-pane lane mirror). 2D scrollers gained horizontal (and per-axis) thumb drag: pressing a thumb or track and dragging updates that axis of the shared 2D offset.
* Padded scrollers no longer surface a phantom scrollbar for content that exactly fits: scroll content size is measured from the content origin (after the leading padding), so a fill-width child no longer reads `padX` wider than the viewport on 2D scrollers (and `padY` taller on 1D ones), and the trailing padding cannot surface a bar by itself either. When an axis genuinely overflows, its scroll range now extends past the last child by the trailing padding, so scrolling to the end still reveals it. Fixes the stray horizontal bar under the demo's searchable list.
* Table column resize grab zones span the whole column height (header band plus body cells down to the table pane's bottom edge), and the `UiCursorEwResize` cursor follows the same span, so a column boundary can be found, hovered, and dragged anywhere down the table instead of only on a 4 px strip of the header cell.
* Table header horizontal-scrollbar lane no longer flickers on/off during column resize drags: the `hBar` overflow flag compares the columns' min-width sum against the stable pane viewport (the body scroller's fill width) instead of the header h-scroller's own rect, which is floored at the content width and could never read as overflowing at rest.

Verified pixel-identical against the forced-full path.
* Ghosting guard for grow×grow (page-level) scroll containers: they span the whole window and keep no input-styled well, so on clip frames the strip vacated by scrolled content had no covering draw command and the retained texture showed stale pixels (a ghost of a previous scroll position). * Scrollbar chrome repaints: wheel and keyboard offsets move content via `storePoint` under the `slotTextAreaScroll` slot (not just floating-pane offsets in `storeFloat`), so offset damage now scans both and returns the scroll node's full rect (content viewport plus its scrollbar lane), not the content clip. A wheel at the top, a scroll round-trip, and text refresh no longer leave a stale 1px thumb edge that only a forced-full repaint fixes.
* Expose/occlude: a window redraw event (SDL `SDL_EVENT_WINDOW_EXPOSED` / `SDL_EVENT_WINDOW_OCCLUDED_RESUMING`) marks the frame dirty and forces the next present full, so a restored window never shows a stale backbuffer. Tracked via `inputWindowRedraw` on `Input`.
* Honest present rate: `presentRate` counts actual presents since the previous HUD refresh instead of falling back to `1000/frameMs`, so the debug HUD shows the real frame rate when the app is idle with frames skipping.
* Wait pacing: the present-locked 0 ms wait ("let the display throttle") only applies when vsync is enabled, because `SDL_RenderPresent` is what blocks. With `--vsync=false` a live in-view animation would otherwise spin the loop at max speed and flicker the whole window, so it paces at `animateTimeout` instead. When frames skip (empty damage, e.g. an animation scrolled out of view), it also paces at `animateTimeout` so the loop does not busy-spin.
* Frame-aligned pacing: after a timed-out event wait the loop winds on to the exact frame boundary (bulk `threadDelay`, then a ≤1 ms tail spin) instead of drifting with the event waiter's timer granularity. The pacing period is the window's current display refresh (queried from `SDL_GetCurrentDisplayMode`), so a vsync-less animation runs at the display cadence (16.666 ms on 60 Hz, ~6.9 ms on 144 Hz) rather than a fixed 16 ms clock tick — removes the beat between the two rates. The bounded spin runs only while an animation is actively presenting, so an eternal in-view animation no longer renders with low, uneven frame times.
* Display refresh observability: the debug snapshot carries `dbgRefreshHz` (the pacing target from SDL, with a fallback to the highest same-size mode refresh when the current mode reports 0), shown in the HUD (`Display`) and in `NANO_FRAME_TRACE=1` output so measured presents can be compared against the pacing target.
* Event-wait overrun: the paced wait now sleeps ~2 ms short of the frame period so the frame-boundary spin absorbs SDL's event-waiter overrun; without it the loop cadence settled ~1 ms late and vsync-less animation looked uneven.
* Float-clock precision: the demo's progress sweep used `realToFrac <$> getMonotonicTime`, which quantizes wall-clock seconds to 'Float' (~3 ms lost at 8 h uptime, coarser than an 8.3 ms frame at 120 Hz) and made the bar edge step. Clock math now stays in 'Double'.
* Time/clock API: `NanoUI.Monad.uiTime` is the monotonic seconds clock as a 'Double', for time-based animation math (never funnel it through 'Float'). `pulse` / `keepAnimating` in `Widgets.Animate` (re-exported through `nanoui`): `pulse period` yields a smooth clock-driven `[0,1]` sine sweep and `keepAnimating resp` holds a wall-clock widget live forever so the frame loop keeps it repainting; `progressBar =<< pulse 6` + `keepAnimating resp` replaces the old manual `getMonotonicTime` + eternal `startAnimation` demo pattern. `stopAnimation` (from `NanoUI.Context` and `NanoUI.Testing`) freezes a running animation in place at its current value and keeps the context from reporting as animating.
* Search debounce timing moved to a new `storeDouble` store slot: the trailing-edge window is measured in 'Double' wall-clock seconds, so it stops shifting (or skipping) at long uptimes where Float loses resolution (~125 ms at 12 days).
* A perpetual animation whose widget leaves the arena (a `keepAnimating` progress bar behind a tab switch) no longer forces a whole-window repaint forever. `writeDamage` only escalates a rect-less live animation to `DamageFull` for the first `orphanEscalateFrames` (2) consecutive frames it is missing, tracked by a per-key rect-less frame counter maintained in `updatePrevRects`. A fresh animation on a widget that is about to be laid out still gets full coverage for those first frames.
* RGFW flicker: the RGFW backend no longer unconditionally clears, re-renders, and re-blits the whole window on every loop tick. It now sleeps blocking until the first event when idle (skip frames do no work at all), paces live animations at the refresh period (`optRefreshHz`, default probe→60 Hz) instead of a fixed 8.3 ms spin, and only present when the frame actually needs repainting (damage, running animation, settle frame, text editing, or a pointer/scroll edge). A new `RGFW_waitForEvent` binding (blocking/polling wait over the display connection) backs the gated event waiter. The opening frame is presented before the loop so the window has content immediately.
