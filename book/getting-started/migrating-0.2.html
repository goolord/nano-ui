nano-ui Documentation

Migrating from 0.1 to 0.2

Version 0.2 brings a concrete NanoUI monad, Var-based state, an opaque Layout API, typed fragment shaders, and cleaner package boundaries. This guide lists the breaking changes encountered when porting real applications from 0.1 to 0.2.

Cabal dependencies and project setup

All nano-ui* packages now version in lockstep at 0.2.0.0 with ^>=0.2 bounds.

build-depends:
  , nano-ui      ^>=0.2
  , nano-ui-sdl  ^>=0.2
  -- optional, if you use NanoUI.Emit or runSdlAppReduce:
  , nano-ui-emit ^>=0.2

If you pin this repository from Git in a cabal.project, add packages/nano-ui-ttf to your subdir: list because nano-ui-sdl now shares its SDL3_ttf text layer through nano-ui-ttf (its +sdl flag defaults to true). If you have tests: True globally in cabal.project, also include packages/nano-ui-shader (or set tests: False on package nano-ui-sdl). Remove any stale +simd or -simd flag on nano-ui-sdl.

Monad and IO

Views no longer carry an effectful constraint.

0.10.2
Ui :> es => Eff es aNanoUI a
uiIO actionliftIO action
Mixing other effectful effects directlyImport NanoUI.Effectful (NanoUIEs, Ui, embedNanoUI, withRunInNanoUI)
runUi from NanoUI / NanoUI.BackendrunUi from NanoUI.Effectful, or runNanoUI from NanoUI.Backend

State and Var

Hooks (useState, useInt, useFloat, useFlag, useText, useEnum, useToggle, useTableSort, useContextMenu) and StateCell are replaced by Var. Interactive controls and overlays take a Var directly and write edits back to it; primed variants return Response.

0.10.2
StateCell a, newState xVar a, newVar x
(v, setV) <- useState cellv <- readVar var, writeVar var v'
modifyState cell fmodifyVar var f
(t, setT) <- useText x; setT =<< textInput tt <- useVar x; textInput t
useInt, useFloat, useFlag, useTextuseVar
useEnumuseEnumVar
useToggleuseVar False with modifyVar v not
useTableSortuseVar (SortCol 0 SortAsc)
useContextMenupopup with a Var (Maybe V2) or Var Bool

(r, a) <- modal open title bodymodal openVar title body (or (r, a) <- modal' (constVar open) title body)

popup open anchor bodypopup openVar anchor body (or popup' for Response)

useTask key action, useStream, useImageRgba, useDrag*Allocate a handle once (newTask, newStream, newImageHandle, newDrag) and pass it first

Keyed scopes (withKey, forEachVar, PaneGrid panes) no longer consume a positional sibling id, so widgets declared after a keyed list keep their focus and state when the list changes.

Typed emission (nano-ui-emit)

NanoUI.Emit, reducer runners (runSdlAppReduce, reduceMessages, reduceUpdates, runFrameE), and reducer test helpers moved to the nano-ui-emit package using NanoUIE msg a without Typeable.

0.10.2
Emit.button "Save" SaveEmit.emitWhen (button "Save") Save
Emit.slider 0 1 val SetValEmit.emitChanged (slider 0 1) val SetVal
Emit.textArea doc SetDocEmit.emitEdited textArea' doc SetDoc
runFrame returning (a, dd, dirty, msgs)runFrame returns (a, dd, dirty); use runFrameE for typed messages

Module splits

Top-level NanoUI now focuses on view code. Specialized widgets, themes, custom drawing, and backend helpers live in dedicated modules:

Built-in themes (tomorrowNightMinDarkTheme, nordTheme, …)NanoUI.Themes
paneGrid, GridNode, PaneGridConfig, PaneGridCtx, PaneDropLocation, paneDragHandleNanoUI.Widgets.PaneGrid

NanoUI also exports selectableRow, collapsing, SortKey, and textCell. If your view defines helpers with those names, hide them on the import NanoUI line or switch to the built-ins.

Layout and widget configs

Layout constructors and fields are no longer exported from NanoUI. Use layout modifiers instead, and pass LayoutModifier (Layout -> Layout) directly to widget config layout fields without applying defaultLayout.

SDL backend (nano-ui-sdl)

Views no longer thread an SdlEnv handle.

Companion packages

  • nano-ui-diagrams: Pass a PlotCache allocated once with newPlotCache to plotting functions.
  • nano-ui-form: Pass a FormState allocated once with newFormState. NanoUI.Form.Named and NanoUI.Form.Unnamed merged into NanoUI.Form.Input using FieldName, and label / separator became formLabel / formSeparator.
  • nano-ui-markdown: Use markdownWith for custom layout modifiers.
  • nano-ui-shader: Renamed select to selectE to avoid clashing with NanoUI.select.
